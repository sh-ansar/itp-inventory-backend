# ITP Inventory — функциональный каталог и права

Состояние исходников на 04.11.2026; детализацию статусов и payload смотреть в docs/API.md и предметных документах. Этот каталог — входная точка поддержки и новых разработчиков.

## Таблица прав (сервер является источником истины)

| Возможность | Viewer | Inventory Manager | Company Admin |
| --- | --- | --- | --- |
| Видеть активы, помещения, склад, инвентаризации и отчеты своей компании | Да | Да | Да |
| Создавать/редактировать актив, перемещение, складскую операцию, инвентаризацию | Нет | Да | Да |
| Создавать/редактировать МОЛ, большинство рабочих справочников | Нет | По разрешенным операциям | Да |
| Архивировать актив, утверждать списание, reopen административной операции | Нет | Нет | Да |
| Управление членством/ролями и настройками компании | Нет | Нет | Да |
| Личный кабинет и смена собственного пароля | Да | Да | Да |
| Доступ к данным чужой компании | Нет | Нет | Нет |

Проверять по реальному endpoint: GET настройки может быть разрешен члену, PUT только администратору. Наличие ссылки/кнопки — не полномочие.

## 1. Основные средства (Assets)
Создать → записать инвентарный номер/тип/место/МОЛ/серийный номер/модель → изменить с version → просмотреть историю → переместить/QR/массовые операции → архивировать с причиной (админ). Состояния active / written_off / disposed. История всегда доступна с проверкой прав.

## 2. Объекты и планы
Создать объект с названием/адресом → этажи → помещения → разместить имущество на схеме; можно изменять размеры, положение, фон и привязку. Запрет циклов, чужих дочерних узлов и дублирующих placements; версии и аудит.

## 3. Материально ответственные
Вести МОЛ/подразделения, активный/неактивный статус; назначать одному или пакетом активов; массовое назначение/перемещение с reason и одной транзакцией. Права и tenant ID перепроверяются перед записью.

## 4. Склады
Номенклатура и склады, движения receipt/issue/transfer, остатки, история, единицы измерения. Смешанные units отображаются по типу; нельзя складывать килограммы и штуки как одно количество. Изменение складского баланса по авторизованной операции.

## 5. Инвентаризации (Stocktakes)
Новая сессия по объекту/выбранным активам → immutable snapshot → QR scan и ручной count → recount → complete → отчет CSV/XLSX/печать; reopen требует административного права. Переезд имущества после снимка не меняет исторический перечень. См. docs/STOCKTAKES.md.

## 6. Списание и утилизация
Черновик и документы → отправить на согласование → возврат на доработку / утверждение администратором → disposal act и audit trail. Приватные файлы нельзя открывать по чужой компании. См. docs/ASSET_DISPOSAL.md.

## 7. Справочники и карточки
Базовые типы оборудования плюс company-specific категории/производители/модели/единицы/подразделения. Редактирование и архивирование сохраняют ссылки/историю. На каждую категорию можно задать динамические поля (тип, подписи RU/EN/GE, required), значения сохраняются атомарно с активом и валидируются API.

## 8. Отчеты и документы
Реестры, сводные по состояниям/объектам/МОЛ, фильтры и печатные формы; XLSX и CSV экранируют формулы, права проверяются перед экспортом. Компания может создавать черновики шаблонов, публиковать версии и видеть предварительный результат; подписи документов не приравниваются к юридически значимой ЭЦП.

## 9. Компания и пользователь
Список членств, роли с защитой последнего админа, смена компании без утечки данных, личный кабинет/пароль, реквизиты, локаль, нумерация. Нет открытой саморегистрации; первая учетная запись создается CLI-оператором.

## 10. Интеграции ERP/1C
Технические endpoint есть в /api/v1/external/companies/{company}, но по умолчанию выключены. Нельзя считать их промышленно принятыми до mapping, dry-run, idempotency, scoped keys, аудита, rate limiting и независимой security review.
